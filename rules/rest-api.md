# REST API

The contract is the OpenAPI document generated by `@nestjs/swagger`. The plan writes the contract before the code
(routes, fields, errors); Spectral checks the generated OpenAPI in the gate.

## Rules

| Rule | Wrong → right | Why |
|---|---|---|
| **kebab-case** segments | `/ticketTypes` → `/ticket-types` | one pattern, readable in the URL |
| **No verbs in the path** (approve, cancel, create, delete, send, verify, login, update, get…) | `POST /registrations/1/cancel` → `POST /registrations/1/cancellations` or a `PATCH` of the status | the HTTP method is the verb; the resource is a noun |
| **No front-end/caller names** in the path (admin, backoffice, internal, public, app, web…) | `/admin/events` → `/events` with role-based authorization | who can call it is authorization, not the URL |
| **No secrets in path/query** (code, password, secret, token, key…) | `GET /invites?token=…` → token in the body or a header | URLs end up in logs and history |
| A creation `POST` answers **201** with `Location` when the resource is readable | | the client knows where what it created lives |
| Collections are **paginated** | | see [scale.md](scale.md) |
| Errors in **Problem Details** format (RFC 9457) | | one error format for every client |

Exceptions by name only: `/oauth2/*`, `/health`, `/me`, `/.well-known/*`.

**Enforced by:** Spectral with ligeirinho's `spectral-ruleset`, in the gate. A new exception requires a change to
the project's `.ligeirinho.yml` with a comment giving the reason.
